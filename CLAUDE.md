# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

SchoolCraft is a French-language educational PWA for 4–7 year olds (moyenne section to CP) with three learning activities: **Lire** (phonological awareness → letters and sounds → syllables → words → sentences), **Écrire** (tracing capitals, digits and cursive letters with the finger) and **Compter** (counting, quick-look, comparing, a linear number race (1–20 is one path that turns back under 10), decomposing, additions, story problems, 11–20). Correct answers earn blocks, which are spent colouring pixel-art heroes (a collectible album) and building a house. A daily adventure (one game of each activity) opens a chest of special blocks. Vanilla TypeScript + Vite, no framework, no backend: everything is saved in `localStorage`. All user-facing text and speech is French; the child cannot read, so every instruction is spoken. The pedagogical choices and their research sources are in `docs/ETUDE.md`. The current state, the proposals waiting for the owner's decision and the voice credit budget are in `HANDOFF.md`; `AGENTS.md` sums up the working rules.

## Commands

```bash
npm install
npm run dev        # Vite dev server (--host, reachable from a phone on the LAN)
npm run check      # validates src/content (heroes, words, levels, glyph strokes, tips); needs Node >= 22.6 (--experimental-strip-types)
npm run build      # tsc --noEmit && vite build → dist/
npm run preview    # serve dist/ (the service worker is only registered in production builds)
npx tsc --noEmit   # type-check only
node --experimental-strip-types scripts/voice/lines.ts      # list every sentence the app can say → scripts/voice/lines.json
node scripts/voice/review.mjs <out.html> [audio prefix]      # a listening page to tick the clips that sound wrong
ELEVENLABS_API_KEY=… node scripts/voice/generate.mjs [--limit N]   # record the missing ones with ElevenLabs (needs ELEVENLABS_API_KEY, paid plan for the « Adina » voice)
```

There is no unit-test runner or linter. CI (`.github/workflows/deploy.yml`) runs `npm ci`, `npm run check`, `npm run build` and deploys `dist/` to GitHub Pages on every push to `main` (Pages source must be "GitHub Actions"). `vite.config.ts` uses `base: './'` so the site works under the `/schoolcraft/` sub-path.

**Testing in a browser (dev server only, stripped from production builds):**
- `?mute` replaces the voice by a log in `window.__said` (no sound; `say()` resolves after 60 ms). `window.__missing` lists the sentences that have no recorded clip. `?quiet` plays the clips muted and logs in `window.__voice` whether each text came from a clip or the device voice (clips need a first real click in the frame, like on a device). Use it instead of stubbing `speechSynthesis` (headless Chromium has no voices, and a stub installed after load misses the first sentences).
- `#play=sounds:7` (or `write:N`, `count:N`) opens a level directly.
- Phone layouts: load the app in an `<iframe>` sized 390×700 (portrait) or 780×360 (landscape) from a page on the same origin that is **not** the app itself (e.g. `/manifest.webmanifest`); `contentWindow.__said` and `contentDocument` are reachable from there. Every iframe shares the same `localStorage`.

## Architecture

**Screens and navigation.** Each screen is a function `xxxScreen(ctx: Ctx)` in `src/screens/` that appends DOM built with the `h()` helper (`src/ui.ts`). `go(name, activity?)` in `src/main.ts` is the router (`map` takes the activity whose map to show): it ticks the play clock, redirects to the `pause` screen when the parents' time limit is exceeded, then calls `beginScreen()` (`src/nav.ts`). `beginScreen()` increments a screen token, stops speech, removes `.overlay` dialogs, scrolls to top and clears the root. It returns `alive()`, `say()` and `wait()` scoped to that screen. **Async work in a screen must go through `ctx.say` / `ctx.wait` and check `ctx.alive()` before acting**, otherwise speech or timers from a screen the child left will talk over, or navigate away from, the next one. `rewardScreen()` is reached from inside a session, not via `go()`, so it calls `beginScreen()` itself.

Home → map of an activity (`screens/map.ts`: levels grouped in chapters, stars, the current level glows, locked levels) → activity. The "Niveau N" button of an activity opens its map. The daily adventure card on home goes straight into the next activity not played today. The reward screen announces the next step (« Maintenant, on va écrire ! ») only after the game that advanced the adventure (`logGame()` returns true), not after every level a child chooses to play on.

**Sessions** (`src/game.ts`). The three activities share `activityScreen()` (`screens/activity.ts`), which builds the `Game` of the current level and calls `runSession()`. A game type implements `setup(r)` (render a question without speaking, return its stats key), `ask(r)` (speak it), optionally `repeat(r)`, `praise`, `noReview`, `rounds`. It answers through the `Round` it receives: `r.win(el, after)` (praise, then `after()` e.g. say the word, then the next question), `r.miss(el)` (shake, oops; the first miss records the item as missed), `r.hold(on)` (block answers during an animation), `r.open()` (this question is shown and waits), `r.say` / `r.wait` (scoped to the question: dropped once the next question is shown). Per-question state lives in the game's closure. The engine owns progress squares, praise (process praise after a retry: « Tu as réessayé, et tu as trouvé ! »), Pixel's reactions, and slips **one review question** from one of the four previous levels before the last question (dashed progress square; it does not count for passing). The first question is rendered immediately and asked once the level intro has been spoken. Rounds: 6 for Lire, 5 for Écrire and Compter (the race is 5 turns). Right answers go into the day's log at once (`logGood`, the parents' week), the finished game into the daily adventure (`logGame`).

**Help grows with each mistake** (use `r.misses`). Lire: 1st mistake, Pixel names what was touched and repeats the question; 2nd, the answers already tried fade away (`fadeTried()`, never a block still needed later in the word) and a clue is given (the sound with its word, the syllables, the syllable to find, the model word again); 3rd, the right answer shines (`showAnswer()`, « Regarde celui qui brille ! »). Compter: from the 2nd mistake Pixel counts with the child (`countTogether()`, « On compte ensemble ! »), the cave shows its places; at the 3rd the right answer shines (`shine()`, « Regarde celui qui brille ! »); comparing (two answers only) shines it at the 2nd. The other Lire games follow the same ladder: tapping syllables names their number and shows one empty box per syllable at the 2nd mistake, « On compte ensemble ! » at the 3rd; spelling gives the word's syllables (or the vowel to find, « Cherche : a. ») at the 2nd and makes the next letter shine at the 3rd; a riddle is reread at the 1st, read aloud with the tried pictures faded at the 2nd, shown at the 3rd; a true-or-false sentence is read aloud at the 1st mistake and the answer shines at the 2nd (only two buttons). Text the child must read (riddles) is read aloud only from the second mistake. Never leave a child repeating the same failure with the same sentence.

**After a success, show what is said.** A found word is said as its syllables, then the word in a short French sentence (`syllableLine()`: « sa… pin… ça fait : sapin ! »; a one-syllable word with its article, `wordLine()` and `ARTICLES`: « Le pain ! »; alone, a repeated word could take an English accent). Its syllables appear under the answers and light up one by one as the voice says them (`sayWord()`): the recorded clips carry the time of each syllable (`src/voiceMarks.json`), passed through `say(text, { onMark, marks })`; with the device voice they are spread over time. A found sound pulses while it is said; rhyming pictures light up as they are named, and after a first-sound answer the two words are written with their shared beginning in gold (`showOnset()`, only when the letters are the same: « cadeau » / « kiwi » share a sound, not a letter). « Taper les syllabes » keeps the drum greyed and locked until its instruction is over (children tap as soon as they see it; the other games accept an answer during the instruction), says the syllables in one timed clip (« Écoute : mo… to. »), a beat lighting with each, and the picture card re-plays « Écoute : moto. » (a syllable or a word said alone could sound English).

Game types live in `src/games/`: `reading.ts` (clap, rhyme, initial, sound, word, build, spell, read, sentence, riddle), `counting.ts` (count, flash, frame, compare, digits, race, hide, make10, add, problem, tens) and `trace.ts` (writing). The voice never reads what the child must read (read/sentence/riddle levels), except to help after a mistake.

**Tracing** (`games/trace.ts`). A glyph is a list of strokes (SVG path data) in a box 100 high. Each stroke is sampled into checkpoints every 2 units once the board is in the page (`getTotalLength`). The finger must start near the green dot; ink only advances to the farthest checkpoint within reach in order (no skipping ahead, so shortcuts and backwards tracing do nothing). Lifting the finger keeps the progress (start again at the green dot shown where it stopped). Going farther than the off-path distance stops the stroke; the first slip is free, the second counts as a miss, every third one replays the demo (announced by the voice, then « Continue au point vert… »). A touch away from the green dot says where to start (at most every 4 s), and a finger that moves while the ink waits makes the dot pulse. Tolerances are set in screen pixels and converted to box units with the board's current scale. Pixel shows each glyph first (animated pen) while saying its name and a word (« Voici la lettre : èle, comme lune. »); the "Sans modèle" level hides the path. A traced glyph turns into a wall of blocks.

**Content is data**, separate from the code: `src/content/reading.ts` (31 levels in 7 chapters, in the order of French CP phonics methods; `kind` is `clap` | `rhyme` | `initial` | `sound` | `word` | `build` | `spell` | `read` | `sentence` | `riddle`; `PIC_WORDS` is the picture bank for phonology with oral syllables, rhyme and first-sound groups; words are written `mou-ton` with silent letters in brackets, `lou[p]`, shown in grey; spelling tiles come from `graphemes(text, parts)`, cut syllable by syllable, a vowel before n or m being nasal only when no vowel follows (« do-mi-no » is d·o·m·i·n·o, not « in »); an item's `group` marks other spellings of the same sound (o, au, eau), never offered together; each level lists what it `teaches` and `npm run check` uses `decode()` to refuse a word that needs a grapheme not taught yet, sentences included, apart from `SIGHT_WORDS`), `src/content/writing.ts` (glyph strokes for capitals, digits and cursive, letter names for the voice, 12 levels in 3 chapters), `src/content/counting.ts` (16 levels in 4 chapters; `mode` per level; story-problem objects), `src/content/heroes.ts` (12 heroes), `src/content/tips.ts` (offline activities for the parents, one list per chapter). Every level has a `chapter`. `src/levels.ts` derives `MAX_LEVEL`, level and chapter names from these files, the class starting points (`GRADE_START`) and clamps the stored levels to them. `scripts/check-content.ts` imports the content files with explicit `.ts` extensions and runs under Node type stripping. Content files must therefore stay import-free and use only erasable TypeScript syntax (no enums or namespaces).

**Levels are stored by number.** Inserting or reordering levels changes what a stored number means: add a mapping (see `V3_LEVELS` and `V4_READING` in `state.ts`, chained by `migrateLevel()`; stars are moved too) and bump the state `version`.

**State** (`src/state.ts`) is a single mutable `state` object, with an internal `version` (currently 4). `sanitize()` repairs malformed saves and migrates old ones: v1 → v2 removed the free grass floor from the build world; v2 → v3 moved the reading and counting levels to their new numbers and added the Écrire activity, stars, the daily adventure, chests, a 60-day history and the class (`settings.grade`, `null` = the welcome dialog asks the parents); v3 → v4 renumbered reading (19 → 31 levels) and its stars. Any change to the state shape needs matching code in `sanitize()`, and a `version` bump when old data must be transformed. Stats keys are prefixed and hold Leitner boxes 1–3: `snd:`, `spell:`, `clap:`, `rime:`, `onset:`, `phrase:`, `devinette:`, `write:<cap|dig|cur>:<char>`, `count:<mode>:…`. `pickWeighted(items, keyFn, avoid)` does the spaced repetition, so the key function must produce the same prefixed key that `setup()` returns. A level is passed with ≥ 80 % first-try answers (`endSession`, which also stores 0–3 stars).

**Children (profiles).** Up to 4 children, listed under `schoolcraft:profiles`. Each has their own save: the first child keeps the original key `schoolcraft:v1` (saves made before profiles exist are theirs), the others use `schoolcraft:v1:<id>`. `switchProfile()` reloads the page on the other save. Home shows the child's avatar (a hero) and asks « Qui joue ? » once per visit when there are several, before the welcome dialog of a child whose class is not set (so the class goes on the right save). `saveProfiles(pick?)` only changes the stored `current` when a child is picked, and the `storage` listener also takes the profile list from another tab. A save that `sanitize()` cannot read is kept aside under `<key>:broken` before the app starts afresh (the next save would overwrite it). A hidden tab never saves (play clock), and a `storage` listener reloads the state when another tab saved, so two open tabs do not overwrite each other.

**Reward economy.** Rewards are earned, not farmed (expected rewards handed out per answer lower intrinsic motivation; see `docs/ETUDE.md`). **Heroes wake up with stars**: hero number *i* can be coloured once `totalStars()` (all levels, all activities) reaches `starsNeeded(i)` = 3 + 5*i; `readyHero()` is the next hero when it is ready (or already started), `starsLine()` says « Encore trois étoiles, et un ami se réveille ! ». Nothing is stored for this: it is derived from the stars, so old saves keep their awake heroes and no migration was needed. Colouring is free. **Blocks come with the finished game**, by its stars (`gameBlocks()`: 1 or 2 common blocks, or 2 common + 1 gold for 3 stars; a single block when the game does not beat the level's star record, so replaying a level pays only by doing better); they are given in `runSession()` before the reward screen, which says « Tes étoiles réveillent un ami ! » when the game made a hero ready. Special blocks (`brick`, `leaves`, `flower`, `crystal`) only come from the daily chest (`screens/chest.ts`: once a day, after one finished game of each activity; no streak to keep). After the chest, a soft end: « Tu as bien travaillé aujourd'hui ! À demain ? » with « À demain ! » (the `rest` screen, Pixel asleep, the house button still leads home) or « Encore un peu ». Blocks only serve the house. **Pixel's challenges** (`src/challenge.ts`, shown in `screens/build.ts`): Pixel's bubble shows a model, a tower of N blocks (the number and a block) or a pattern to copy or to copy and continue (the blocks, then dashed « ? » slots); a pattern is named block by block, each one lighting up. The child builds it in the house with their own blocks; only blocks placed since the challenge started count (a tower is a whole column of exactly N new blocks; a pattern is N new blocks in a row, old house blocks may touch it), and it is judged after a 2-second pause, so stacking without counting does not pass by luck. A tower that is too tall is counted for the child at once (« Ta tour a six blocs. Il en faut quatre. »), one too short after the pause. A finished row that is not the pattern (`wrongPattern()`) is a mistake, and help grows: the 1st one names the pattern again (« Pas tout à fait. Écoute bien le motif ! », then, for a pattern to continue, the « ? » slots blink with « Et après, qu'est-ce qui vient ? À toi de trouver la suite ! »), from the 2nd the « ? » slots show the blocks that come next and the whole pattern is named. `PLANS` sets the order, harder as `state.challenges` grows (a counter added without a version bump), and a challenge needs no more blocks than the child owns, in the inventory or in the house; a smaller challenge offered when blocks are short does not move the plan on. Every other line Pixel says in the house goes through its local `say()` (a name `lines.ts` scans), which stops the naming of a pattern. A success shows a ★ button for the next one; no blocks are given for it. Build mode places and refunds inventory blocks (special blocks appear in its palette once owned); the ground under the build grid is decorative. Hero grids are 14 rows × 12 columns: `.` is empty, `k` is outline, `e` is eyes (they blink); any other letter is a colour zone from `palette` (6 at most, numbered in key order). `currentHero()` repairs a hero that is fully coloured but not yet marked done. The hero is added to `done` in the same save as its last zone.

**Touch handling** (`installTapFix` in `src/ui.ts`). Buttons and `.px.zone` cells are activated by the code itself on `pointerup`, with 28 px of tolerance, so long presses, slightly moving fingers and taps on the 3D shadow still count. The browser's own click for that gesture is then cancelled: `touchend.preventDefault()` for touch, and clicks with `detail > 0` are swallowed. Without this, a "ghost" click lands on whatever the new screen shows under the finger. Consequences:
- New tappable things should be `<button>`s; their handlers run from a synthetic `el.click()`.
- `button img`, `button svg` and `button span` have `pointer-events: none`.
- Game targets use `touch-action: none` (the tracing board too; it handles raw pointer events itself).

**Speech and text** (`src/audio.ts`). Pixel's voice is recorded: `say()` cuts a text into sentences (`sentences()` in `src/voiceKey.ts`, shared with the scripts), looks each one up in `src/voice.json` (sentence key → file in `public/voice/`) and plays the clips in order (never slowed down: they already have their pauses) through one `<audio>` element fed with blob URLs (Safari does not play media answered by a service worker without byte ranges). A sentence with no clip can be played piece by piece when it is cut by « … » (« mouton… bateau… »); otherwise the whole text is spoken by the device's Web Speech voice (`fr-FR`, ranked automatically, each sentence with its own tone). `say()` cancels whatever was being said and never rejects. The parents can choose a device voice instead (per device, `localStorage` key `schoolcraft:voice`: '' = recorded voice, `device` = best device voice, or a voice URI). The first touch primes the `<audio>` element (iOS), and `navigator.audioSession.type = 'playback'` keeps the voice on with the ringer switch off. **Recording:** `scripts/voice/lines.ts` lists every sentence (literals given to `say()`, plus every template expanded over the content and the number ranges the games use); `scripts/voice/generate.mjs` records the missing ones with ElevenLabs (`eleven_v4`, voice « Adina », praise with `[happily]`), trims the silence and encodes 40 kbps mono MP3 with ffmpeg, checks sentences of 10+ letters with speech-to-text (retries below 80 % similarity; homophones such as « lo » / « l'eau » score low and are fine), **sounds, syllables and words said alone are sent in IPA between slashes**: a line of `lines.ts` can carry `say` (the text sent, e.g. « Celui-là, c'est : no. » is sent « Celui-là, c'est le son : /no/. », « va… lise… ça fait : valise ! » is sent « [calmly] /va/. /liz/. Ça fait : valise ! ») and `marks` (the characters where each syllable and the word start); `ipa()`, `soundIpa()` and `spokenSyllables()` in `content/reading.ts` give the IPA (written out, the voice read « no » as « numéro », « xi » as « onze », « che » as « tché », many syllables as English, and pronounced silent letters). A text that starts with a slash makes the voice say « slash », so such texts start with `[calmly]`; an IPA clip is always checked by speech-to-text for « slash » (3 tries, then once with the plain text). `scripts/voice/say-as.json` can still respell a sentence by key (a string, or `{ say, marks }` for a syllable sentence: « Écoute : o… mar. » is sent « Écoute : eau. marre. »; eleven_v4 ignores `<break>` tags); syllables without IPA are sent with dots instead of « … » (« pu. ma. Puma ! »: with « … » the voice drawls) and `SYLLABLE_AS` respells one read as English (« to » → « tôt »). `--redo-match <regex>` / `--redo-file <file>` record again the sentences that match or are listed (`--only`: just those, `--budget N`: at most N credits, `--dry-run`: show what would be sent); syllable sentences go through the `with-timestamps` endpoint to get their marks; it writes `src/voiceMarks.json`, `src/voice.json` and `scripts/voice/clips.json` (text sent, cost, transcript, score). **When you change or add a spoken sentence, run both scripts**; until then the device voice says it, and `npm run check` fails if a listed clip file is missing or unused. Speech needs a first touch on some devices, so screens reached at launch do not rely on speaking. Sound effects are synthesised with Web Audio (no audio files); phone speakers play almost nothing under ~250 Hz, so a low sound needs an audible attack (the drum has a noise burst). Rules for spoken phrases, partly enforced by `npm run check`:
- Never put a word that triggers a liaison (« dans », « les », « c'est », « des », « plus »…) right before an item that starts with a vowel. Write « comme école », not « comme dans école ». Story-problem objects start with a consonant.
- Put « : » before the item in instructions (« Touche le mot : avion »).
- Don't say « tes/les héros » (some voices say « tes-z-héros »); say « tes amis ».
- Elide before vowels (« L'orange »).
- Keep praise gender-neutral, and praise the effort or the strategy, not the child.
- Avoid repeating the level intro in the first question (both are spoken back to back).

Letter names for the voice (`LETTER_SPEECH`) are the letter itself (`f`, not `èfe`, which voices read « è-feu »), except `euh`, `hache`, `double vé` and `i grec` (`ku` is read « cou » and `cu` is spelled « cé u »). Item `speak` strings are spelled so the voice says the sound rather than the letter name (`e` → `euh`, `in` → `hein`, `oi` → `oua`); phonology words carry their oral syllables spelled for the voice (`pa-pi-yon`), and words whose syllable count is debatable (« ce-rise ») are `noClap`; the clap game also leaves out every word ending in a silent e after a consonant (« bouche »: one syllable in standard French, two when the e is said, as in the South; Eduscol advises to avoid them). Bubbles go through `bubble()` / `setBubble()`, which add French no-break spaces (`fr()`). Dialogs use `modal()`, never `window.prompt` / `confirm`.

**Layout.** All CSS is in `src/style.css` and is mobile-first. A `(orientation: landscape) and (max-height: 500px)` block switches the activity, colouring and build screens to a two-column grid for phones held sideways. Grid cells are sized with `--cell` / `--pile` / `--sq` / `--board` custom properties, not `aspect-ratio`.

**PWA.** `src/sw.js` is a template, not a file in `public/`. A plugin in `vite.config.ts` replaces `__VERSION__` and `__ASSETS__` (the list of hashed build files) and emits `dist/sw.js`; the build fails if a placeholder is left. `/assets/*` (the Andika font included: it is self-hosted in `src/fonts/`, latin subset only, so no request goes to Google) is served cache-first, matched with `ignoreVary` because some servers send `Vary: Origin`. Everything else is network-first, falling back to the cache after 3 s. Each build version gets its own cache, and old ones are deleted on activate, except `schoolcraft-voice`: the voice clips are cache-first there, filled in the background 8 s after load by `prefetchVoice()` (which also deletes clips no longer listed).

**Parents area and play time.** The parents area is behind a multiplication question (`parentGate`). It holds the children (names, avatars), the class (applies `GRADE_START`, never moves a child back), the week's play time, progress per skill, offline activities for the current chapter, the method, the time limit and the reset. The time limit lives in `src/playtime.ts`: it ticks every 5 s, counts only visible time (also logged per day for the parents), and resets after a 30-minute break. Free-play screens (home, map, album, build) are sent to the pause screen by the tick; other screens reach it on their next `go()`. **First launch** (`screens/welcome.ts`, shown by home while `settings.grade` is null, so also for each new child): one dialog in two written steps, the class then a time limit per sitting (10, 15 pre-selected, 20 min or none); then, if the parents' area was never opened on this device, a coach mark points at « Parents ». Pixel stays quiet during both, then introduces itself (« Coucou ! Je suis Pixel… », the same text as a tap on the fox) before the usual home instruction; a child who has not finished a game yet hears this introduction once per launch. A dot stays on that button until the parents' area is opened once (device-wide `localStorage` key `schoolcraft:parents-seen`, not in the save).

## Project rules

- Characters and art must be original. The universe is only *inspired* by block-building games: do not reproduce existing characters, names, textures or sounds from Minecraft or any other franchise (see `docs/PLAN.md`). The mascot, heroes, blocks and chest are pixel art drawn in code.
- No ads, no tracking, no account, no microphone, no child data leaves the device.
